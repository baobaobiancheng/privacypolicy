# 隐私政策生成器交接文档

## 1. 项目是什么

这是一个面向中国境内 App 的隐私政策事实收集和文档生成系统。它不是“输入产品名就自动写政策”的通用文本工具，而是先让用户确认产品真实的个人信息处理行为，再根据确认事实查询法规、生成 Markdown，并制作 Word。

产品原则只有三条：

1. 用户填写的产品事实是唯一事实源。
2. AI 可以发现矛盾、整理表述，但不得自行补造产品事实。
3. 生成结果投入使用前，仍需公司法务或合规人员结合真实业务复核。

## 3. 用户看到的主流程

```text
选择 39 类产品之一
  → 使用前确认
  → 1. 基本信息
  → 2. 功能与个人信息
  → 3. 设备权限
  → 4. SDK 与合作方
  → 5. 存储与安全
  → 6. 用户权利
  → 7. 隐私政策生成
```

第 7 环节的服务端流程：

```text
提交生成任务
  → 事实核对（不强制三轮，最多三轮）
  → 用户确认待核对项
  → 查询相关法规
  → DeepSeek 组织正文
  → 结构与事实校验
  → 制作并存储 Word
```

## 4. 技术架构

| 层 | 实现 | 关键位置 |
| --- | --- | --- |
| Web | Next.js 16 + React 19 | `app/`、`components/` |
| 表单合同 | Zod + 版本化 JSON | `src/workspace/contract.ts` |
| 39 类产品 | 类别注册表、问卷定义、开发模拟场景 | `src/categories/`、`src/questionnaires/`、`src/workspace/development-scenarios.ts` |
| API | Next.js Route Handlers，统一 `/api/v1` 错误合同 | `app/api/`、`src/http/` |
| 数据 | MySQL 8 + Prisma | `prisma/schema.prisma`、`prisma/migrations/` |
| 生成任务 | 独立 Worker，租约、心跳、退避和幂等 | `scripts/generation-worker.ts`、`src/application/generation/` |
| 模型 | DeepSeek 事实预检与正文生成 | `src/ai/` |
| 法规 | 百鉴 MCP 法规关键词查询 | `src/law/baijian.ts` |
| 文档 | Markdown 预览 + OOXML Word | `src/documents/`、`src/storage/report-storage.ts` |
| 埋点 | 页面、按钮、漏斗、生成、上传、下载和 AI 问答事件 | `components/analytics-tracker.tsx`、`src/analytics/` |

数据库里的 `Project.formData` 是问卷唯一事实源。生成任务保存提交时的项目修订号和输入哈希；生成期间项目被修改时，旧报告会标记为 `SUPERSEDED`，不会覆盖当前版本。

## 5. 文档和数据如何使用

### 5.1 竞品隐私政策

`03-竞品隐私政策材料/` 覆盖 39 类、91 个产品目录，包括官方页面快照、完整文本、第三方共享页面和结构化提取表。它们用于：

- 确定各类产品的常见功能和个人信息选项。
- 对照隐私政策章节、固定表述和第三方披露方式。
- 回溯问卷选项或生成规则的证据。

这些材料不会在每次生成时全部发给模型。

### 5.2 法规材料

`04-法规与知识库材料/已获取数据/law_detail_results.json` 包含 437 条详情记录，按 `lawId` 去重后是 354 部法规。这是完整候选资料池，不是当前运行时的全量知识库。

当前运行时会根据事实预检生成的关键词，通过百鉴 MCP 查询最多 5 个关键词，每个返回最多 3 条现行有效法规，最多 3 路并发，单请求超时 30 秒。本地 354 部法规尚未建成全量检索索引，不要将“文件已入库”误解为“运行时已使用”。

### 5.3 律师模板

`05-律师模板与成品样例/` 是生成结构和固定表述的核心验收依据。对应的逐项差距已记在 `01-项目背景与产品设计/设计文档/隐私政策结构逐项核对报告.md`。

## 6. 本地从零运行

### 6.1 前置条件

- Node.js，版本以仓库当前 Next.js 16 兼容要求为准。
- MySQL 8.x。
- 可用的 DeepSeek API Key。
- 需要法规查询时，配置百鉴 App Key 和 App Secret。

### 6.2 初始化

```bash
git clone <repository-url> privacypolicy
cd privacypolicy
cp .env.example .env.local
npm ci
npm run db:generate
npm run db:migrate:deploy
```

编辑 `.env.local`，至少配置：

```dotenv
DATABASE_URL="mysql://<user>:<password>@127.0.0.1:3306/<database>"
DEEPSEEK_API_KEY="<server-side-secret>"
BAIJIAN_APP_KEY="<server-side-secret>"
BAIJIAN_APP_SECRET="<server-side-secret>"
```

开发演示数据开关：

```dotenv
NEXT_PUBLIC_DEV_FORM_DEFAULTS="true"
```

正式上线前必须设为 `false`。当前尚未接入 SSO/OIDC；仅内部演示服务器使用生产构建时，才可临时配置 `ALLOW_DEV_PERSONA="1"`。该开关不得作为真实生产认证方案。

### 6.3 启动

终端一：

```bash
npm run dev -- --hostname 127.0.0.1 --port 3000
```

终端二：

```bash
npm run worker
```

访问 `http://127.0.0.1:3000`。Web 和 Worker 必须连接同一个 MySQL。

## 7. 部署与更新

当前部署是单机 Web + Worker，可使用 PM2。以端口 `3100` 为例：

```bash
cd /home/<deploy-user>/privacypolicy
npm ci
npm run db:generate
npm run db:migrate:deploy
npm run check

pm2 delete privacy-policy-web 2>/dev/null || true
pm2 start npm --name privacy-policy-web --cwd "$PWD" -- run start -- --hostname 0.0.0.0 --port 3100

pm2 delete privacy-policy-worker 2>/dev/null || true
pm2 start npm --name privacy-policy-worker --cwd "$PWD" -- run worker

pm2 save
```

后续常规更新：

```bash
cd /home/<deploy-user>/privacypolicy
git pull --ff-only origin main
npm ci
npm run db:generate
npm run db:migrate:deploy
npm run check
pm2 restart privacy-policy-web --update-env
pm2 restart privacy-policy-worker --update-env
pm2 save
```

启动后检查：

```bash
pm2 status
pm2 logs privacy-policy-web --lines 50 --nostream
pm2 logs privacy-policy-worker --lines 50 --nostream
curl -I http://127.0.0.1:3100/
```

## 8. 开发和验收门禁

必须通过：

```bash
npm run lint
npm run typecheck
npm test
npm run db:validate
npm run build
npm audit --omit=dev
```

有独立测试数据库时再运行：

```bash
RUN_MYSQL_INTEGRATION=1 npm run test:integration
```

核心人工验收路径：

1. 39 类入口均可创建项目，且模拟数据符合具体类别。
2. 七步表单可保存、退出、恢复，多窗口修改冲突不覆盖本地输入。
3. 生成前事实核对最多三轮；已确认项不重复阻断。
4. 法规查询、正文生成、Markdown 预览和 Word 下载完整走通。
5. 项目修改后旧报告不被当作当前版本。
6. 上传、AI 问答或埋点失败不得破坏主业务响应。

## 9. 当前边界和上线阻断项

当前可用于开发和内部演示，不应宣称已完成独立生产上线。真实对外使用前至少还需要：

- 接入上层平台 SSO/OIDC，删除生产开发身份开关。
- 上传文件的魔数校验、恶意文件扫描和隔离解析。
- MySQL 自动备份、恢复演练和数据保留策略。
- Web/Worker 健康检查、主动告警和统一日志采集。
- CSP、安全响应头、反向代理、HTTPS 和请求体限制。
- 报告对象存储方案。当前 Word 保存于 MySQL `LongBlob`。
- 浏览器 E2E、真实模型冒烟和 Word/WPS 视觉验收。

## 10. 凭据和敏感数据

- 不要将 `.env.local`、数据库密码、DeepSeek Key、百鉴 App Key/App Secret 提交到 Git。
- `04-法规与知识库材料/调用代码/key.md` 被 `.gitignore` 显式排除。可参考同目录的 `key.example.md`，但推荐使用 `BAIJIAN_APP_KEY` 和 `BAIJIAN_APP_SECRET` 环境变量。
- 竞品政策和法规原文是内部研究资料。对外发布、商业分发或二次使用前，应重新核对来源、时效和权利边界。

## 12. 出现问题时先看哪里

| 现象 | 先检查 |
| --- | --- |
| 页面打不开 | `pm2 status`、Web 日志、端口监听、反向代理配置 |
| 项目创建失败 | MySQL 连接、迁移状态、当前身份配置 |
| 生成一直排队 | Worker 进程、`generation_jobs` 状态、租约和 `nextAttemptAt` |
| 事实核对反复出现 | 用户确认的 issue 哈希、项目 revision、最多三轮状态 |
| 法规查询失败 | `BAIJIAN_APP_KEY`、`BAIJIAN_APP_SECRET`、MCP 网络和 30 秒超时 |
| 正文生成失败 | `DEEPSEEK_API_KEY`、模型名、Worker 日志、任务重试状态 |
| Word 无法下载 | 报告鉴权、`reports.docx`、项目 revision 和浏览器 Network |

维护原则：先区分本地构建、Web 进程、Worker 进程、外部法规接口、模型请求和最终业务验收，不要用“页面能打开”代替完整链路验收。

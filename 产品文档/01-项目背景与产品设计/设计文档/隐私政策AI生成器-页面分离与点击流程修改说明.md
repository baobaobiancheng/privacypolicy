# 隐私政策 AI 生成器页面分离与点击流程修改说明

修订日期：2026-08-10  
状态：APPROVED FOR DOCUMENT UPDATE  
本轮范围：分析并修改产品与 UI 文档，不修改应用代码

## 一、修改结论

当前页面的视觉方向可以保留，但页面职责必须重新划分：

1. `/` 只作为产品展示页，负责解释产品是什么、为什么可信、如何协作以及从哪里开始。
2. 点击“开始填写”或“进入地图类试点”后，必须离开展示页，进入独立的项目工作区 `/projects/new/scope`。
3. 展示页不得嵌入可交互工作区、可填写表单、功能选择状态、开发身份切换器或草稿生成控件。
4. 工作区使用独立布局，保留截图中的左侧步骤导航、顶部项目状态和右侧任务内容区。
5. 工作区内所有看起来可点击、可填写、可保存、可生成或可下载的控件，都必须产生真实状态变化或明确的失败反馈；不得只改变本地视觉状态。

页面分离后，两套界面同时存在，但职责互不混用：

```text
产品展示页                              项目工作区
理解产品、建立信任、开始使用            收集事实、保存进度、复核、生成草稿

/                                      /projects
  ├── 产品价值                           ├── 项目列表
  ├── 证据边界                           ├── /projects/new/scope
  ├── 填写流程                           └── /projects/[id]/...
  ├── 协作角色
  └── 开始填写 ─────────────────────────> 独立工作区布局
```

## 二、当前流程问题分析

### 2.1 产品展示页和工作区混在同一长页面

当前“开始填写”执行页内滚动，把用户带到展示页下方的“可交互工作区”。用户无法判断自己是在体验产品介绍，还是已经开始建立正式项目。浏览器地址、页面导航和视觉外壳都没有发生变化，缺少明确的任务边界。

修改后，“开始填写”是页面跳转，不是锚点滚动。新页面加载后立刻显示工作区外壳和“适用范围”第一步。

### 2.2 展示模块伪装成真实业务操作

展示页中的功能场景可以展开、选择，并显示“查看当前选择”，但这些选择不属于正式项目数据。它会让用户误以为自己已经开始填写，随后进入工作区时又看到另一套功能选择，形成重复和不信任。

修改后，展示页只说明“五组场景如何帮助防遗漏”。场景内容可以静态展示或展开阅读，但不得出现复选框、“已选择”“选择功能”“查看当前选择”等业务状态。

### 2.3 工作区存在只改变界面、不完成任务的控件

当前纵切片中存在以下类型的不完整交互：

- “保存并退出”没有保存和离开结果。
- “转律师处理”没有创建范围停止状态、待办或导出范围信息。
- 通用信息可以输入，但未形成明确的保存成功、失败和版本冲突反馈。
- 功能选择后可以直接去复核，缺少逐功能处理活动详情填写。
- 字段确认、功能选择和自定义功能主要停留在页面本地状态。
- 草稿预览使用固定示例文字，未证明来自当前项目已确认事实。
- “生成工作草稿”与真实快照、阻断检查、失败恢复和下载记录没有形成完整的页面反馈链。
- 开发身份切换只改变显示身份时，容易让用户误以为服务端权限已经切换。

修改后的设计必须把“能点击”升级为“能完成任务”。

## 三、页面与布局边界

### 3.1 产品展示页 `/`

只保留以下内容：

1. 品牌和一句产品定位。
2. 主要动作“开始填写”。
3. 次要动作“查看证据边界”。
4. 法规、律师整理、参考政策、客户事实和律师判断的边界说明。
5. 五步填写流程说明。
6. 客户法务、产品技术和律师的协作分工。
7. 末尾再次出现“进入地图类试点”。
8. 官方法规原文等真实外部链接。

从展示页删除：

- Hero 右侧模拟工作区窗口。
- 整个“可交互工作区”模块。
- 工作区侧栏、项目完成度和步骤切换。
- 功能选择复选框和“已选择”状态。
- “查看当前选择”。
- 通用披露输入框、字段确认、草稿预览和下载按钮。
- 开发身份切换器。
- 任何会让用户误以为答案已保存到项目的控件。

### 3.2 项目工作区 `/projects/**`

工作区采用截图所示的独立结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ 左侧项目与步骤导航 │ 顶部：完成度、保存状态、保存并退出      │
│                    ├────────────────────────────────────────│
│ 1 适用范围         │                                        │
│ 2 通用信息         │ 当前步骤标题                            │
│ 3 功能与信息       │ 当前步骤表单、规则、错误和主要动作      │
│ 4 复核             │                                        │
│ 5 生成草稿         │                                        │
└─────────────────────────────────────────────────────────────┘
```

工作区不再展示营销 Hero、证据宣传区、角色轮播或末尾宣传 CTA。必要的法规解释以当前任务旁的证据卡、抽屉或原文链接出现。

### 3.3 路由合同

```text
/                                      产品展示页
/projects                              项目列表
/projects/new/scope                    新项目范围门禁，不在 GET 时创建项目
/projects/[id]/scope                   已创建项目的范围门禁
/projects/[id]/profile                 通用披露信息
/projects/[id]/features                五组功能选择
/projects/[id]/activities/[activityId] 处理活动详情
/projects/[id]/tasks                   待办清单
/projects/[id]/review                  处理活动总览
/projects/[id]/draft                   草稿预览与生成
/projects/[id]/exports                 导出记录
```

从 `/projects/new/scope` 提交首个有效答案时创建项目并取得 `project_id`。不能因为用户只点击“开始填写”就创建空项目。

## 四、产品展示页点击流程合同

展示页只有“导航、了解和开始”三类交互，不承担项目填写。

| 位置 | 控件文案 | 控件类型 | 点击结果 | 失败或边界 |
|---|---|---|---|---|
| 顶部品牌 | 知证 | 内部链接 | 返回 `/` 顶部 | 当前已在顶部时不产生额外状态 |
| 顶部导航 | 证据边界 | 页内锚点 | 滚动到 `#evidence`，标题获得程序焦点 | 减少动效模式下直接定位 |
| 顶部导航 | 填写流程 | 页内锚点 | 滚动到 `#process` | 不进入工作区 |
| 顶部导航 | 律师复核 | 页内锚点 | 滚动到 `#review` | 不切换身份 |
| Hero 主动作 | 开始填写 | 路由链接 | 跳转 `/projects/new/scope`，显示工作区第一步 | 导航期间显示按钮等待状态，失败时保留在展示页并提示重试 |
| Hero 次动作 | 查看证据边界 | 页内锚点 | 滚动到 `#evidence` | 不创建项目 |
| 证据区 | 查看法规原文 | 外部链接 | 新标签打开官方法规页面 | 使用外链标识并保留当前页面 |
| 场景说明 | 展开了解 | 说明型手风琴 | 只展开解释、来源和常见遗漏 | 不允许选择，不形成项目答案 |
| 协作角色 | 上一位/下一位 | 内容切换 | 切换角色职责说明 | 只影响展示内容 |
| 页面末尾 | 进入地图类试点 | 路由链接 | 与“开始填写”相同，跳转 `/projects/new/scope` | 不滚动到本页内模块 |
| 页脚 | 证据边界/填写流程 | 页内锚点 | 定位对应展示章节 | 不改变项目状态 |
| 页脚 | 返回顶部 | 页内锚点 | 返回页面顶部 | 支持键盘激活 |

展示页不得出现无去向按钮。暂未实现的能力使用普通说明文字，不渲染成按钮、链接、输入框或复选框。

## 五、工作区完整用户流程

```text
[展示页开始填写]
        │
        v
[新项目范围门禁]
  ├── 不支持 -> [保存范围结论] -> [转律师说明/导出范围信息] -> [项目列表]
  └── 支持
        │提交时创建项目
        v
[通用披露信息]
        │真实保存
        v
[功能选择]
        │每个已选功能必须进入详情
        v
[处理活动详情 × N]
        ├── 已知 -> 字段级确认
        └── 不确定 -> 创建角色待办
        v
[待办与处理活动总览]
  ├── SCOPE_STOP / EXPORT_BLOCK / CONFLICT -> 返回具体字段
  └── 仅 WARNING / REVIEW_FLAG -> 允许显式占位符
        v
[草稿预览]
        │冻结输入快照
        v
[生成 DOCX]
  ├── 失败 -> 保留快照并安全重试
  └── 成功 -> 下载 + 导出记录
```

### 5.1 步骤导航

- 当前步骤高亮。
- 已完成步骤可返回查看和修改。
- 未完成的未来步骤不可直接进入；点击时说明前置条件，不允许绕过必填或范围门禁。
- 修改已完成步骤后，如果依赖值改变，相关确认和当前草稿状态立即失效。

### 5.2 保存并退出

点击后执行真实保存：

1. 校验当前页面可以保存的字段。
2. 提交 `command_id + expected_project_revision`。
3. 成功后显示“已保存”及时间，再返回 `/projects`。
4. 版本冲突时不退出，显示冲突字段和重新载入入口。
5. 网络或数据库失败时保留页面输入，显示可重试提示。

### 5.3 范围门禁

- 四项分别填写，不使用总开关。
- “确认并继续”只有四项均明确且首期支持时可用。
- “转律师处理”必须保存 `SCOPE_STOP` 原因，并提供“导出已填范围信息”和“返回项目列表”。
- 法规原文链接真实可打开，规则卡明确写“不是客户事实”。

### 5.4 通用披露

- 输入框使用受控值并显示保存状态。
- 每一组支持“已知”“不确定”“不适用”，其中“不确定”必须指定产品、技术或律师负责人。
- “保存并选择功能”成功保存后才进入 `/features`。
- 输入错误聚焦到具体字段；不能用默认示例值伪装成客户已填写。

### 5.5 功能和处理活动

- 功能候选默认未选，定位和导航也只作为推荐项，不自动成为客户事实。
- 选择功能后创建或启用处理活动草稿，仍处于未确认状态。
- “确认功能”不能直接跳到复核；所有已选功能必须先完成处理活动详情或创建待办。
- “添加表单中没有的功能”打开真实结构化表单，至少填写功能名称、实际目的、是否已上线和负责人；保存后出现在项目活动列表。
- 删除自定义功能需要二次确认，并说明会使哪些确认和草稿失效。

### 5.6 复核与返回修改

- 摘要数字由服务端规则结果产生，不使用固定示例值。
- 点击阻断、待办或活动行，返回具体字段并把焦点放在问题处。
- “预览草稿”只在没有 `SCOPE_STOP`、`EXPORT_BLOCK` 和事实冲突时可用。
- 一般待确认项允许继续，但必须显示将进入正文的占位符和复核附录数量。

### 5.7 生成和下载

- 预览正文只读取当前项目快照，不显示固定产品示例。
- 第一次点击“生成工作草稿”创建不可变快照并进入 `GENERATING`。
- 成功后按钮变为“下载工作草稿”，并新增一条导出记录。
- 重复点击相同输入和幂等键返回同一结果。
- 失败显示稳定错误码、失败原因和“使用同一快照重试”。
- 文件名、项目修订号、内容版本、模板版本和生成时间在页面可见。

## 六、真实交互状态矩阵

| 功能 | 加载中 | 空状态 | 失败 | 成功 | 部分完成 |
|---|---|---|---|---|---|
| 展示页开始填写 | CTA 禁用并显示“正在进入” | 不适用 | 保留页面并提示重试 | 进入范围工作区 | 不创建空项目 |
| 项目列表 | 骨架行 | 解释首期用途并显示“创建地图类项目” | 显示重新加载 | 显示项目状态和最近草稿 | 项目卡显示待办与阻断数量 |
| 范围门禁 | 恢复已填答案 | 四项未答，主动作禁用 | 保留答案并提示保存失败 | 进入通用披露 | 不支持范围显示停止页 |
| 通用披露 | 字段保留，按钮显示保存中 | 分组显示尚未填写和负责人 | 字段错误或版本冲突可定位 | 保存时间和新 revision 可见 | 不确定项转待办 |
| 功能选择 | 候选加载骨架 | 显示五组冻结场景和自定义入口 | 内容版本错误阻断进入 | 已选功能进入活动列表 | 已选但未完成详情显示待处理 |
| 活动详情 | 保存按钮忙碌 | 未选候选保持未确认 | 保存失败或冲突不丢输入 | 记录确认人、角色和时间 | 不确定字段创建待办 |
| 处理活动总览 | 规则计算中 | 无已选功能时返回功能选择 | 规则失败默认阻断 | 显示可导出状态 | 警告、律师复核和占位符并列 |
| 草稿生成 | `PENDING/GENERATING` 状态可见 | 无可生成活动时不给空白文档 | `FAILED` 保留快照和重试 | `SUCCEEDED` 可下载 | 生成期间项目修改不改变旧快照 |

## 七、用户旅程与感受

| 步骤 | 用户行为 | 目标感受 | 设计支持 |
|---|---|---|---|
| 1 | 浏览产品展示页 | 快速理解，不被表单打断 | 一页只解释价值、证据边界和流程 |
| 2 | 点击开始填写 | 明确进入正式任务 | 地址和页面外壳同时改变，显示工作区第一步 |
| 3 | 完成范围判断 | 知道产品是否适用 | 四项独立回答，停止原因可解释 |
| 4 | 填写事实 | 不怕遗漏，也不被迫猜测 | 分组表单、不确定答案和角色待办 |
| 5 | 复核问题 | 清楚下一步找谁 | 阻断按对象和负责人排列，可返回原字段 |
| 6 | 生成草稿 | 相信文件来自自己的答案 | 快照版本、占位符和证据映射可见 |
| 7 | 交给律师 | 知道草稿不是批准版 | 水印、复核附录和离线复核说明 |

## 九、实施任务

- [ ] **T1（P1）页面拆分**：将产品展示页和项目工作区拆成独立布局与路由；展示页删除所有业务表单状态。
- [ ] **T2（P1）CTA 路由**：顶部与底部主 CTA 统一进入 `/projects/new/scope`，不创建空项目。
- [ ] **T3（P1）展示页点击合同**：逐一实现本文件第四节的锚点、外链和路由结果，删除无去向控件。
- [ ] **T4（P1）工作区真实保存**：将范围、通用披露、功能、活动和确认接入项目 revision 与事务命令。
- [ ] **T5（P1）步骤门禁**：未来步骤不可绕过，阻断项可返回并聚焦具体字段。
- [ ] **T6（P1）真实草稿链路**：预览读取当前快照，生成、失败、重试、下载和导出记录形成闭环。
- [ ] **T7（P2）交互状态测试**：按第六节状态矩阵补齐页面测试和端到端点击测试。

## 十、不在本轮范围

- 不修改现有 Next.js、React、CSS、API、Prisma 或 DOCX 代码。
- 不改变已批准的颜色、字体和总体视觉气质。
- 不增加 39 类 App 分类、跨境、多类别或正式批准版能力。
- 不在产品展示页提供试填模式；需要体验时直接进入可保存的工作区。

## 十一、可复用资产

- 工作区视觉方向复用用户提供的截图和现有左侧步骤导航结构。
- 证据分层、颜色、来源标签和水印继续遵循《隐私政策 AI 生成器 UI 设计规范》。
- 地图五组场景、通用披露和规则配置继续使用 `map-v1` 内容包。
- 现有 HTML 线框图仅代表工作区流程，不再作为产品展示页中的嵌入模块。

## 十二、文档验收标准

- 阅读产品展示页规范时，无法误解为“可以在本页填写项目”。
- “开始填写”和“进入地图类试点”都只有一个明确去向。
- 展示页每个可点击元素在第四节都有结果定义。

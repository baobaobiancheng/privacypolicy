# 隐私政策 AI 生成器会议纪要

来源：`20260821154840-陈东的预定-逐字稿文本-1.txt`  
会议时长：约 43 分钟  
整理日期：2026-08-24

> 说明：逐字稿未提供真实姓名与角色映射。以下将主要表达法律边界、法规依据和政策条款的人称为“法律/律师方意见”，正式归档前应由参会人确认说话人身份。

## 一、法律/律师方的核心观点

### 1. 一期范围先锁定中国境内

- 首期只生成适用中国大陆法律法规的隐私政策，不处理境外版本、跨境传输和境外法律义务。
- 产品宣传应明确“当前支持中国境内场景，境外能力后续上线”。
- 如果客户选择境外存储或无法确认云服务商机房位置，不能继续套用境内模板，应提示确认存储地点，并进入单独的跨境合规分支或人工处理。

依据：00:05:22–00:06:03、00:28:55–00:30:14。

### 2. 产品类别以主要功能为准

- 先以地图导航作为主功能完成首期，不因存在少量重叠功能就把项目复杂化。
- 客户不确定类别时，在选择页面提供简短解释，例如“以定位、路线规划、导航为主要功能的产品通常属于地图导航类”。
- 产品同时涉及地图、社交等多个类别时，可以先展示模型识别出的候选类别，由客户自行选择；多类别合并生成属于后续能力，不作为地图一期的必做范围。

依据：00:06:03–00:07:28、00:40:31–00:42:57。

### 3. 事实收集必须让客户少填，但不能替客户臆造

- 常见地图功能、字段、处理目的应预置为可勾选选项，让客户通过“处理/不处理”或“有/无”完成确认。
- 对预置内容，客户需要确认其与实际产品相符；系统不能把参考 App 的内容直接当成客户事实。
- 预置无法覆盖的功能、字段、SDK、第三方合作方，必须保留手动填写入口。
- 交互要做到“看得懂、会勾选”，减少长文本和法律术语；但必填项未完成时不得进入下一步，只允许暂存。

依据：00:09:17–00:12:07、00:37:48–00:38:19。

### 4. 隐私政策的第一核心是“收集和使用”

- 先让客户说明：有什么功能、处理哪些个人信息、处理目的是什么、保存多久。
- 这些事实可以直接生成“我们如何收集和使用个人信息”章节，例如“当您使用地图导航服务时，我们会处理位置、出发地、到达地等信息，用于路线规划和导航”。
- 保存期限对小客户通常难以确定，允许使用“仅在提供服务所必需的期限内保存”等合规模板；客户明确承诺具体年限时，再使用客户填写的年限。
- 政策其他章节可使用经法律方整理的通用套话，但涉及客户事实的部分仍必须来自客户选择或填写。

依据：00:11:14–00:14:27、00:20:31–00:22:40、00:27:53–00:28:12。

### 5. 六个模块应按政策结构组织

会议反复确认的模块是：

1. 功能、信息字段与处理目的；
2. 设备权限；
3. SDK；
4. 第三方共享/合作方；
5. 存储地点、保存期限和到期处理；
6. 个人信息主体权利与联系方式。

安全措施、未成年人保护等可以先作为后置模块或通用模板，不作为地图一期的主要阻塞点；但正式政策生成时应保留相应章节或明确“不适用”。

依据：00:15:54–00:18:28、00:25:38–00:27:29、00:31:14–00:36:48。

### 6. 权限、SDK和共享不能只依赖模型猜测

- 权限：列出地图常见权限，如定位、蓝牙、相册/文件访问，由客户勾选实际调用的权限，并确认使用目的；其他权限允许手填。
- SDK：客户可手填，也可上传 SDK 清单、接口文档或技术说明，由系统辅助解析；解析结果只能作为候选，不能自动写入正文。
- 第三方共享：地图项目不一定有固定合作方，因此先询问是否向第三方提供个人信息；若有，要求填写合作方身份、处理目的和涉及信息。SDK 与线下服务商/开票商等第三方要区分披露。

依据：00:16:10–00:18:59、00:31:34–00:36:11。

### 7. 存储地点和保存期限要有默认模板与分支

- 默认按境内存储设计，生成境内存储的固定表述。
- 客户如果只知道“使用某云服务”但不知道机房位置，应提示其向云服务商确认境内/境外；不确认就不能把“境内”当成事实。
- 保存期限默认使用服务必要期限、注销后删除/匿名化等通用表述；客户明确选择 5 年等期限时，必须按客户承诺生成。
- 如果选择境外存储，应切换到跨境合规问题清单，不得继续生成仅适用于境内的套话。

依据：00:19:44–00:22:40、00:28:55–00:30:14。

### 8. 行权联系方式是实际可用的入口

- 至少收集一个客户可实际接收请求的客服电话或客服邮箱。
- 其他权利说明（查阅、复制、更正、删除、撤回同意、注销等）可以使用通用模板，政策中统一写明通过该联系方式提交请求。
- 邮寄等低频方式一期不作为重点。

依据：00:23:08–00:25:38。

### 9. 生成过程应可解释、可重复生成

- 生成前应有检查、确认、法规查询等阶段反馈。
- 生成正文时显示当前章节和实时进度，完成后再生成 Word。
- 客户后续变更功能、权限、SDK 或处理信息后，应能重新进入对应问卷并重新生成；一期先完成首次生成，变更生成作为后续迭代。

依据：00:38:30–00:39:47。

### 10. 法规知识应先筛选，再进入模型上下文

- 法律方提供核心法规名单，产品团队先按“个人信息保护、个人信息、App”等关键词筛选已有法规数据。
- 筛选后由法律方确认纳入范围，再用于 AI 助手解释、规则判断和政策生成。
- 不要求一期接入全部法规；先建立少量、与地图和 App 个人信息处理直接相关的法规基线。

依据：00:39:47–00:40:35。

## 二、会议形成的产品流程

### 首期主流程

1. 选择中国境内产品与地图导航类；页面提供类别解释。
2. 选择地图核心功能。
3. 对每个功能选择对应个人信息字段、处理目的、保存期限。
4. 选择设备权限及每项权限的使用目的。
5. 填写或上传 SDK 信息，系统解析后供客户确认。
6. 填写第三方共享/合作方信息；没有则明确选择“无”。
7. 选择存储地点、保存期限和到期处理方式；境外或不确定时触发提示/分支。
8. 填写客服邮箱或电话，生成个人信息主体权利章节。
9. 补充安全措施等通用信息，检查必填项。
10. 调用已确认的法规资料和客户事实生成政策正文及 Word。

“六步”是信息组织方式；产品可以保留更多页面，但每页必须对应上述模块，避免把所有字段混在一张表里。

## 三、明确会议待办

### A. 法律/律师方

- [ ] 提供首期核心法规名单，优先覆盖：个人信息保护法、App 必要个人信息范围、个人信息处理规则、敏感个人信息、个人信息主体权利、跨境传输等与地图/App直接相关内容。
- [ ] 确认法规筛选关键词和纳入/排除标准；首期不追求覆盖全部法规数据。
- [ ] 提供地图导航常见功能、信息字段、处理目的的冻结清单。
- [ ] 提供境内存储、必要期限、注销删除/匿名化、行权、安全措施等通用模板，并标出“可直接套用”的固定文本。
- [ ] 确认境外存储/跨境场景的阻断提示和后续处理方式。
- [ ] 确认第三方共享、委托处理、共同处理、SDK 披露的字段要求和展示格式。
- [ ] 审阅一期生成样例，确认哪些内容属于通用套话、哪些内容必须由客户填写。

### B. 产品/交互

- [ ] 将表单重构为“功能 → 信息字段 → 处理目的 → 保存期限”的关联式选择，不再全局混选字段。
- [ ] 每个模块使用“常见选项勾选 + 其他手动输入”，并统一提供“无/不适用”。
- [ ] 设计六模块流程和顶部进度反馈，必填项未完成时阻止下一步但支持暂存。
- [ ] 在地图类入口增加类别解释和“中国境内能力”范围提示。
- [ ] 增加 SDK/技术文档上传入口；上传后展示解析候选，要求客户确认后才能进入生成输入。
- [ ] 增加第三方共享手填卡片：合作方、身份/类型、处理目的、涉及字段、合作方式。
- [ ] 增加存储地点不确定、境外存储、保存期限未确定的分支提示。
- [ ] 增加“重新生成/变更信息”的产品入口，为后续版本保留数据结构。

### C. 技术/AI

- [ ] AI 助手读取当前项目已确认表单、对话和上传文件，并可将结构化事实以候选方式回填表单。
- [ ] 上传文件解析支持 SDK 文档、平台规则、产品介绍等常见材料；解析失败时保留原文件和人工填写入口。
- [ ] 仅将已发布的法规资料、通用模板和已确认客户事实发送给生成模型；参考 App 内容不能直接成为客户事实。
- [ ] 生成前根据已确认事实生成法规关键词，优先查询本地法规数据；查询结果经筛选后再进入模型上下文。
- [ ] 生成模型输出前先完成事实矛盾提示；矛盾项展示给客户修改，不能静默选择一个版本。
- [ ] 生成结果按章节反馈实时进度，完成校验后生成 Word；不得把模型思考内容直接展示给客户。
- [ ] 记录输入表单 JSON、法规版本、模板版本、模型版本和生成时间，支持后续重新生成。
- [ ] 对模型输出做结构、必备章节、客户事实引用和敏感内容校验；校验失败要显示具体原因和可修复入口。

## 四、一期范围边界

### 纳入

- 中国境内单产品；
- 地图导航主功能；
- 功能/字段/目的/期限；
- 权限、SDK、第三方共享、存储、行权；
- 本地法规关键词检索；
- AI 助手辅助填写；
- Markdown 预览与 Word 导出；
- 不完整时暂存，完整后生成草稿。

### 暂不纳入或需人工处理

- 境外版本及跨境合规政策自动生成；
- 多个 App 类别的合并生成；
- 无法确认机房位置的存储事实；
- 客户未提供名称、目的、字段等关键第三方信息；
- 未经客户确认的 SDK/模型推断结果；
- 全部 39 类一次性完善；
- 未成年人、复杂广告画像、算法备案等复杂专题的深度自动化。

## 五、需要特别确认的开放问题

1. 逐字稿中提到的“六步”最终页面顺序，是将“共享”放在 SDK 后，还是放在存储前？
2. “保存期限未确定”是否允许直接生成，还是必须客户选择“按服务必要期限模板”？
3. 第三方共享是否在一期只做客户手填，还是需要进一步提供常见合作类型选项？
4. SDK 文档解析一期支持哪些格式（DOCX、PDF、TXT、图片），解析候选的确认粒度是按 SDK、按字段还是按活动？
5. 法律方提供的固定模板是否允许模型改写，还是只能进行变量替换？
6. 生成的首期交付物命名为“隐私政策草稿”还是“待发布隐私政策”，以及是否需要客户法务二次审阅提示？

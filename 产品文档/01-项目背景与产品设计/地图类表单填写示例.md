# 地图类隐私政策表单填写示例

以下示例以“行迹地图”为例，展示客户如何填写地图导航类首期表单。示例内容是客户事实输入，不代表系统已经作出法律必要性或合规结论；处理依据、敏感信息、第三方角色和最终文字仍由律师复核。

## 一、项目基本情况

| 字段 | 示例填写 |
|---|---|
| 运营主体全称 | 杭州行迹科技有限公司 |
| 运营主体联系信息 | 浙江省杭州市西湖区示例路 88 号 |
| 产品名称 | 行迹地图 |
| 产品版本 | Android 2.4 |
| 隐私联系邮箱 | privacy@xingji.example |
| 用户权利请求入口 | App「我的」→「设置」→「隐私中心」→「个人信息权利」 |
| 权利请求响应方式和期限 | 用户提交申请后，客服在 15 个工作日内通过 App 消息或邮件回复 |
| 未成年人信息实际处理情况 | 产品不以未成年人为主要用户；如发现未成年人信息，将转人工核查并按规则处理 |
| 安全措施概述 | 访问权限分级、传输加密、生产环境最小权限、操作日志审计 |
| 个人信息事件通知渠道 | 隐私联系邮箱、App 公告和官方网站通知 |
| 政策生效日期 | 2026-08-10 |
| 政策更新通知方式 | App 弹窗、隐私政策页面提示和版本更新说明 |

## 二、范围门禁

四项均选择“是”：

- 只生成一个产品的一份中国境内版隐私政策；
- 产品以地图、定位或导航为主要功能；
- 不同时属于支付、网约车或社区等其他类别；
- 不涉及向境外提供个人信息。

## 三、选择的功能和处理活动

### 1. 定位和导航

- 处理目的：提供当前位置展示、路线规划、步行和驾车导航。
- 保存期限规则：导航过程中使用实时定位；导航结束后删除原始轨迹，必要的统计信息去标识化后保存 30 天。
- 字段：位置信息、出发地、到达地。
- 客户确认：以上三个字段均确认产品实际处理。

### 2. 实时路况与智能交通

- 处理目的：根据道路位置和交通变化展示拥堵情况、预计到达时间和路线建议。
- 保存期限规则：实时路况数据在服务结束后删除；聚合统计数据去标识化后保存 90 天。
- 字段：位置信息、道路位置、使用时间。
- 客户确认：以上三个字段均确认产品实际处理。
- 律师提示：该功能属于可选功能，必要性和拒绝后的功能影响需要单独判断。

### 3. 安全保障服务

- 处理目的：识别异常登录、定位请求滥用和崩溃问题，保障服务稳定与账号安全。
- 保存期限规则：安全日志保存 30 天；崩溃日志保存至问题关闭后 90 天。
- 字段：设备标识符、系统版本、IP 地址、崩溃日志。
- 客户确认：设备标识符、系统版本、IP 地址已确认；崩溃日志是否长期保存待技术负责人补充。
- 律师提示：设备标识符、IP 地址和日志字段不因“安全保障”目的而当然属于必要信息。

## 四、表单外补充信息

> 使用高德定位 SDK，仅在用户点击“开始导航”后调用前台定位；用户停止导航后不再持续获取位置。SDK 不向境外传输数据。地图瓦片服务由公司自建服务转发，暂未接入广告或个性化推荐 SDK。

这段内容会作为 `additionalNotes` 原样送入模型，模型不得把它扩写成未经确认的事实；涉及 SDK 名称、处理者角色、字段和共享关系的内容需要律师和技术负责人复核。

## 六、预期生成结果

模型应生成完整的政策章节，包括：

1. 政策概述和适用范围；
2. 按处理活动说明收集和使用个人信息；
3. 保存期限；
4. 用户权利及请求入口；
5. 委托、共享和第三方说明；
6. 安全措施；
7. 未成年人信息；
8. 政策更新和联系方式。

正文应是连贯的隐私政策语言，而不是字段名称列表。模型无法确认的内容必须保留 `[[待确认:字段]]`，并在文末律师复核附录中列出。
